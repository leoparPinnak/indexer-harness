# Agent Note: 新会话总是开启一个聊天，行内操作在触屏上依然可用

Status: implemented

[English](2026-10-14-new-session-blank-reuse-and-touch-actions.md) | 中文

## 问题

两个故障从同一棵浏览器树到达操作者，都被报告为「这个按钮有时毫无反应」。

新会话会收养当前屏幕上那个空白 Session。收养规则的本意是阻止反复点击堆出空聊天，但它同样作用于显式操作：当操作者正处在一个空白聊天里时点击新会话，只是重新打开了同一个聊天，屏幕上什么都没变。第二条路径则完全不作为：目标 Workspace 取自 Workspace 与 Session 两个 feed 当时持有的内容，而在这些 feed 报告 `ready` 之前到达的点击找不到任何 Workspace，于是走空分支并清空视图。

行内操作（Workspace 行上的 `+` 及其旁边的 `...`）只靠 `:hover` 显现。对于没有 hover 的指针，落在行上的第一次点按既进入该行的 hover 状态，又激活手指下方的东西，因此那次揭开 `+` 的点按打开的是该 Workspace 最近的 Session，而不是新会话；第二次点按才生效。于是哪个按钮看起来可用，只取决于时机。

## 决策

`connectWorkspace` 接受可选的 `excludeSession`，显式的新会话流程传入它正在显示的那个 Session。收养仍然作用于该 Workspace 中其他所有空白成员，因此避免垃圾的机制保持完整；只有已经显示在屏幕上的聊天永远不会被收养。`openWorkspace` 保持其不带过滤的收养，供导航路径使用。

当两个列表 feed 尚未 `ready` 时，`startSession` 等待它们，而不是从部分快照解析目标。feed 已就绪时保留同步快路径，因此空部署分支仍然立即清空。

`Rows.module.css` 在 `@media (hover: none)` 下保持 `.rowActions` 可见，并连同 hover 规则所隐藏的时间戳一起保留。粗指针设备无需先揭开就能拿到这些按钮。

## 曾考虑的替代方案

**总是创建 Session，从不收养空白。** 这是对该按钮最直白的解读，也彻底删掉了这条规则——但那样每次访问 Workspace、每次导航都会产生一个空 Session，而这正是收养规则当初要防止的堆积。

**保留收养规则，改为滚动或高亮被收养的行。** 无需创建聊天就能让点击有可见效果，但操作者要的是新会话；高亮一个他本来就看着的行，读起来并不像新会话。

**行内操作仅在首次点按时显现（二次点按的可供性）。** 保持视觉密度，却让每次触屏交互都多花一次点按，而且没有任何提示说明第一次点按只是揭开。

**把触屏规则放进按视口宽度判断的媒体查询。** 宽度并不能标识输入方式：窄的桌面窗口有 hover，而宽的平板没有。

## 后果

- 空白收养规则现在因调用方而异：显式新会话永不收养当前 Session，导航仍然收养。两条路径都有测试钉住。
- feed 就绪前到达的点击会被延后而不是丢弃；如果某个部署的 feed 永不就绪，这次点击会一直待定，这与视图其余部分一致——那时还没有任何东西可被寻址。
- `@media (hover: none)` 规则让粗指针上永久显示操作按钮，因此触屏用户每行最多会看到两个 16px 字形，而鼠标用户只在 hover 时看到。
- 同批落地的 Session 收藏复用了这条规则所使之可点按的行内操作容器。
