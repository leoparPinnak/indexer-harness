# Agent Note: 快速会话 —— 每个会话一个临时文件夹的草稿对话

Status: implemented

[English](2026-10-19-fast-sessions.md) | 中文

## Problem

Web 界面只有一种开始对话的方式：先选一个工作区，再在其中对话。工作区是操作者已经拥有的目录，因此一个探索性的问题——"读一下这个附件"、"试试这段代码"、"看看这个报错"——不得不借用真实项目目录，agent 在其中写下的任何内容都会落到该项目的文件中间。另一种做法是用裸 `cwd` 创建不带工作区的会话，但它无法使用：会话骨架把没有工作区的会话视为尚未开始，输入框会以禁用状态渲染在"选择工作区以开始"占位文案之后。

## Decision

**快速会话是一个拥有宿主为它创建的文件夹的普通会话。** `session.createFast` 生成会话 id，创建 `<fastRoot>/<sessionId>`，在该文件夹上创建工作区，用工作区的规范路径创建会话，再把它挂载上去。除此之外没有任何不同：同一个 Agent、同一份日志、同一套持久化、同样的 `session/…` 事件。用户可见的差别只在于其工作目录所在的位置，以及侧边栏如何对它分组。

**快速会话根目录是部署策略，而不是常量。** `SessionController` 接收 `fastSessionRoot`，默认值为操作系统临时目录下的 `dsh_fast_sessions`，并通过 `session.fastSessionRoot` 报告它。`SessionCommandController.createFast` 按调用接收解析后的根目录，而不是把它作为构造状态持有：根目录是部署输入，以参数传入使命令控制器不必再持有一个托管概念。

**快速会话必须拥有一个工作区。** 每一个 Web 表面——输入框、文件树、在应用中打开、产出文件——都通过会话所拥有的工作区来解析其目录，而不是通过头部里的 `cwd`。只创建文件夹而不创建工作区，得到的对话其输入框是禁用的，这正是第一版实现显现出来的样子：文件夹出现了，会话打开了，而操作者无法输入。在该文件夹上创建工作区，才使会话成为普通且可用的会话，代价是每个快速会话一条持久注册记录。

**工作区标题由客户端提供。** UI 文案归语言字典所有（[决策](2026-08-23-locale-owned-client-ui-copy.zh.md)），因此宿主只把标题当作数据存储，绝不自行发明标签：侧边栏的快速会话按钮通过 `uiWorkspace.startSession` 的姊妹方法 `startFastSession(title)` 传入 `t('session.fast')`。未提供标题的调用方回退到文件夹名，也就是注册表自身的默认值。

**侧边栏拥有分组。** 位于根目录下的会话被固定到收藏下方的独立区段，并从工作区分组中移除：`deriveGroups` 跳过任何 `cwd` 位于根目录之下的会话，以及任何 `path` 位于根目录之下的工作区；`deriveFastSessions` 则以最新优先列出恰好这些会话。两者都把根目录作为值接收；未得到应答的 `session.fastSessionRoot` 读取（空字符串）不分类任何内容，使该区域保持其通常形态，因此没有该动词的部署或传输行为与之前完全一致。

## Consequences

快速会话文件夹在按下按钮时立即创建，且永不被删除：删除会话日志或工作区记录会留下文件夹，而该文件夹会比拥有它的工作区存活更久。草稿文件夹正是临时目录被允许保留的那类残留，因此没有添加清理器；需要清理器的部署可以把 `fastSessionRoot` 指向一个自带生命周期的目录。

每个快速会话都会向持久注册表增加一条工作区记录，而侧边栏分组和工作区选择器是按路径、而不是按标记隐藏这些记录的。因此，若某部署在创建快速会话之后重命名或移动快速会话根目录，这些工作区就会重新作为普通分组出现；根目录本应是稳定的。

## Alternatives considered

**不带工作区的会话。** 这是最简单的宿主侧改动，而它产生的对话操作者无法输入。改为放宽会话骨架的"没有所属工作区"规则，会让每一个工作区被删除的会话悄然变得可对话，而这是关于删除工作区的产品决策，不是关于草稿对话的决策。

**所有快速会话共用一个工作区。** 这会让注册表保持精简，但共享工作区强制共享 `cwd`，而每个会话独立文件夹正是这一特性本身：写入共享草稿目录的 agent 会把每个对话的文件混在一起。

**复用带 `cwd` 的 `session.create`。** 客户端无法先创建文件夹：文件夹以宿主生成的会话 id 命名。在客户端预分配 id 会把宿主的 id 格式复制到浏览器里，并把 `mkdir` 留在创建会话的事务之外。
